# getGCMT

A command-line tool to download [Global Centroid Moment Tensor (GCMT)](https://www.globalcmt.org/) solutions and save them in **CMTSOLUTION** format, which is used by seismic simulation software such as [SPECFEM3D](https://github.com/SPECFEM/specfem3d).

---

## Features

- **Web search mode** — query the GlobalCMT catalog directly by time, magnitude, depth, and geographic range; event IDs are fetched automatically.
- **ID list mode** — supply a plain-text file of GCMT IDs (copied from the GlobalCMT search page) and download each one.
- Supports both new-format IDs (`200502020230A`) and old-format IDs (`010800G`).
- Selectable magnitude type for filtering: Mw, Ms, or Mb.
- Automatic fallback for old-format IDs: if IRIS SPUD returns a wrong event (known substring-match issue), the correct data is fetched directly from GlobalCMT.

## Requirements

- Python 3.8+
- [ObsPy](https://docs.obspy.org/)
- [requests](https://docs.python-requests.org/)

Install dependencies with:

```bash
pip install obspy requests
```

## Usage

### Mode 1 — Web search (automatic)

Query GlobalCMT and download matching events in one step:

```bash
python fetch_gcmt.py -s <start> -e <end> [options] -o CMTSOLUTIONS
```

**Example — deep earthquakes (Mw ≥ 6.5, depth 150–700 km) from 2010 to 2020:**

```bash
python fetch_gcmt.py -s 2010 -e 2020 -mn 6.5 -zn 150 -zx 700 -o CMTSOLUTIONS
```

**Example — subduction zone events filtered by surface-wave magnitude (Ms ≥ 7.0) in the Western Pacific:**

```bash
python fetch_gcmt.py -s 2000 -e 2023 -mn 7.0 --magtype Ms \
    -yn -60 -yx 60 -xn 100 -xx 180 -o CMTSOLUTIONS
```

### Mode 2 — ID list file

Provide a text file containing GCMT IDs (one per line). The first
whitespace-separated token on each line is taken as the ID; the rest is ignored.
Lines starting with `#` are treated as comments.

```bash
python fetch_gcmt.py -i gcmt_id.txt -o CMTSOLUTIONS
```

The ID file can be generated by opening the [GlobalCMT search form](https://www.globalcmt.org/CMTsearch.html), setting your criteria, choosing **Output type: GCMT event name**, and copying the result.

## All Options

| Argument | Default | Description |
|---|---|---|
| `-s`, `--start` | — | Start date: `YYYY`, `YYYY-MM`, or `YYYY-MM-DD` (required in web mode) |
| `-e`, `--end` | — | End date: `YYYY`, `YYYY-MM`, or `YYYY-MM-DD` (required in web mode) |
| `-i`, `--ids-file` | — | Path to a GCMT ID list file (skips web search when given) |
| `-mn`, `--minmag` | `6.0` | Minimum magnitude (web mode only) |
| `-mx`, `--maxmag` | `10.0` | Maximum magnitude (web mode only) |
| `--magtype` | `Mw` | Magnitude type for filter: `Mw` (moment, default), `Ms` (surface wave), `Mb` (body wave) — web mode only |
| `-zn`, `--mindepth` | `0` | Minimum centroid depth in km (web mode only) |
| `-zx`, `--maxdepth` | `1000` | Maximum centroid depth in km (web mode only) |
| `-yn`, `--minlat` | `-90` | Minimum latitude (web mode only) |
| `-yx`, `--maxlat` | `90` | Maximum latitude (web mode only) |
| `-xn`, `--minlon` | `-180` | Minimum longitude (web mode only) |
| `-xx`, `--maxlon` | `180` | Maximum longitude (web mode only) |
| `-o`, `--output` | `CMTSOLUTIONS` | Output file path |

## Output Format

Each event is written as a 13-line **CMTSOLUTION** block, separated by a blank line:

```
 PDEQ 2005  2  2  2 30 18.00  -17.7200  167.8300 255.0  0.0  7.1 VANUATU ISLANDS
event name:      200502020230A
time shift:        2.0000
half duration:     8.5000
latitude:        -17.8500
longitude:       167.9600
depth:           249.0000
Mrr:        1.990000e+26
Mtt:       -7.830000e+25
Mpp:       -1.210000e+26
Mrt:        2.220000e+25
Mrp:       -1.190000e+26
Mtp:        5.870000e+25
```

Moment tensor components are in units of **dyne·cm**.

## Notes

### Old-format IDs and automatic fallback

Old-format IDs (6 digits + letter, e.g. `121800A`) encode the date as `MMDDYY` and correspond to pre-2005 GCMT catalog entries. IRIS SPUD has a known issue where it matches these short IDs as trailing substrings of newer IDs — for example, `121800A` matches inside `201608121800A`, returning a completely different 2016 event.

The tool handles this in two steps:

1. **Detection** — after fetching from IRIS SPUD, the returned event's date is checked against the date encoded in the old-format ID. A mismatch triggers the fallback.
2. **Fallback** — the correct data is fetched directly from GlobalCMT using a narrow date-range query, which returns CMTSOLUTION blocks that are used as-is.

### Other notes

- Depth filtering in web search mode is applied by GlobalCMT on the **centroid depth**.
- A temporary file `temp_gcmt.xml` is created during the run and removed automatically on exit.
